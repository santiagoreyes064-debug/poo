# Solana Copy Trading Platform - Code Review (v1)

**Verdict**: NEEDS_CHANGES

## Issues Found (9)

### Critical Security
1. **Vault program execute_trade drains to arbitrary destination** - The `trade_destination` account is unchecked. An executor can transfer all vault lamports to any address. Must constrain destination or require CPI to DEX program.
2. **Execution service skips user signing flow** - `processOrder` builds and submits transactions directly without routing through WebSocket signing. Must either use the signing flow or implement delegated signing via vault executor.

### Blocking Integration
3. **Auth message format mismatch** - Frontend signs `"Sign this message to authenticate with SCT.\nNonce: ${nonce}"` but backend verifies the raw nonce string. These will never match. Align the message format.
4. **Frontend API path prefix mismatch** - Frontend calls `/api/auth/nonce`, `/api/vault` etc. but gateway routes are `/api/v1/auth/nonce`, `/api/v1/vault`. All requests will 404. Fix frontend API base paths.
5. **getNonce HTTP method mismatch** - Frontend sends GET to `/api/auth/nonce?wallet=...` but backend expects POST with `{ walletAddress }` body.
6. **Frontend WebSocket URL** - Connects to `ws://localhost:3002` but API gateway WebSocket is on port 3001 at `/ws`.

### Architectural Gaps
7. **API gateway in-memory state** - Vault, trader, copy relations stored in arrays. Replace with Prisma calls to PostgreSQL.
8. **No close_positions instruction in vault** - Once positions open, `current_open_positions` never decrements. Add `close_position` instruction.
9. **Redis Streams unbounded growth** - Add MAXLEN trimming to publishToStream calls (use ~10000 approximate trimming).

### Lower Priority
- Daily loss counter counts gross outflow not realized losses (acceptable for v1 with documentation)
